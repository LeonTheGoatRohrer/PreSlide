# PreSlide V0.3 Baseline — event-level error analysis

Generated by `python -m preslide.baseline` from saved predictions; no model was retrained. Record-level table: `event_diagnostics.csv` (local only). Nothing was removed.

## How to read

- Each event group = 1 documented landslide slope + 5 matched pseudo-negative controls, all at the same t0.
- `rank` 1–6 of the positive among its six slopes (1 = model put the landslide first; ties count half). Random ranking: expected rank 3.5, expected controls beaten 2.5, first-place rate 1/6 ≈ 16.7 %.
- Development events (45): V0.2 out-of-training predictions, median rank over 5 repetitions. Original test events (15): frozen V0 models, single prediction. The two sources are reported separately.
- `weather_rank_change` = terrain-only rank − terrain+weather rank (> 0: adding weather moved the landslide up).
- The CSV also holds `*_score_rank`: the rank of the median out-of-training score per slope. The web explorer shows this one, so that the displayed rank always matches the displayed scores. For development events it can differ from the median of the per-repetition ranks used in the tables below.

## Weather distinguishability

- Events whose positive and controls have nearly identical weather (median standardised difference < 0.05): 17/60.
- Events in which any control shares the positive's 1 km INCA cell: 0/60.
- Positive was the wettest of its six slopes (7-day rain): 15/60 (chance ≈ 10).
- Weather differences between nearby slopes therefore exist in the data; whether a 1 km product resolves slope-scale forcing is not established.

## Interpretation

Errors are spread across clusters, position categories and matching quality; the rank distribution is close to the random reference (see the tables above and `reports/null_v03/summary.md`). No single data-quality property explains the poor events. These diagnostics describe the baseline; they were not used to select models, features or events.
